# Off-chain SDKs

Last lecture you sent yourself ADA by hand, with Lace's buttons. But an **app** can't click buttons, it has to build that transaction **in code**. That's what an **off-chain SDK** is for.

"Off-chain" means code that runs **on your computer or server**, not on the blockchain. An off-chain SDK is a library that:

- **reads** the chain, looks up what you currently own (your bags, the UTxOs) and network conditions like the fee rate, the "raw material" it needs to build a valid transaction
- **builds** the transaction, picks which of your bags to spend, packs the tokens into the new bags (the outputs), and works out the change and fee so everything balances
- **signs** it, hands the finished transaction to your wallet, which proves it's really you by signing with your key; the SDK never sees that key itself
- **submits** it, sends the signed transaction to the network, where it's included in a block and takes effect

There's an SDK for almost any language, browse the full set in **[Builder Tools](/tools/?tags=sdk)**. The examples in these lectures use **[Mesh](https://meshsdk.dev/)** and **[Evolution](https://no-witness-labs.github.io/evolution-sdk/)** (both TypeScript). You install one from npm and call it from your app.

## Why you need one

Remember the ledger rule from the last lecture: a transaction's **inputs must equal its outputs plus the fee**. Getting that exactly right by hand, picking enough bags to cover the amount and the fee, then working out the change, is fiddly and easy to get wrong. An SDK does it **automatically**: you say "send 1 ADA to this address," and it balances the transaction for you.

:::tip You don't have to hand-pick
You don't _have to_ hand-pick which bag to spend if you don't need or want to. The SDK selects them for you, and you can still take over for the cases that need it.
:::

Two lines do the balancing for you:

- `await wallet.getUtxos()` hands the SDK **all** your current bags (UTxOs).
- `.selectUtxosFrom(...)` lets it pick from them, and `.complete()` **balances the transaction**: it selects just enough bags to cover the payment plus the fee, and returns the leftover to `.changeAddress(...)` as change.

**Run it and see it on the explorer.** You'll need **[Lace](https://www.lace.io/)** on **Preview** with a little test ADA (from Lecture 1). Grab just this example (no need to clone the whole repo) and start it:

```bash
npx giget@latest gh:cardano-foundation/developer-portal/examples/onboarding/lectures/mesh lectures-mesh
cd lectures-mesh
npm install
npm run dev
```

Open the printed URL in the browser where Lace lives, click **Connect Lace & send 1 ADA to myself**, and approve it. It prints an **explorer link** to your brand-new transaction.

## Try it

Open your transaction on the explorer (the app printed a link) and read it beside the one you sent by hand last lecture, they're the **same shape**: **inputs** (the bags the SDK chose), **outputs** (1 ADA to yourself, plus change), and the **fee**. The only difference is that this time your code built it, and the SDK did the balancing.
